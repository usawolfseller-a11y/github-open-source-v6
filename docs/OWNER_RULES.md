# Правила владельца

Каждое правило здесь — прямое указание владельца канала. Часть из них
родилась из отвергнутых вариантов: если что-то здесь помечено «отвергнуто»,
не предлагайте это снова.

---

## Формат публикаций

### Длинный текст, не фото
Пост идёт **текстовым сообщением** (лимит Bot API 4096 символов), а карточка
прикрепляется **сверху как большой превью-блок** через `link_preview`.
Фото-пост отвергнут: подпись к фото ограничена 1024 символами, и история
не помещается.

### Карточки
- Горизонтальные **1200×630**. Квадрат и портрет — отвергнуты внутри канала.
- Стиль **Editorial Daily** по умолчанию, **Neon Terminal** для CLI/TUI,
  **Glass Aurora** только для AI Brief, **Editorial Sunday** для дайджеста.
- «Обводка не нужна» — рамку вокруг карточки убрать.

### Копирайт
- **Не сухой.** Никаких пресс-релизов и канцелярита.
- **Не заканчивается на «...»**.
- **Заголовки не для разработчиков.** Обычный человек, листающий ленту,
  должен захотеть открыть. Не `jargon`.
- **Технические названия моделей сохраняются полностью**: вендор + точное
  имя продукта + версия. `GPT-6.2`, а не «новая модель OpenAI».
- **Заголовки и подводки разделяются по площадкам:**
  - Telegram и статья — любопытный неспециалист;
  - Bluesky/Mastodon — проще и короче;
  - Facebook — самый простой язык.

### Картинки
- **Всегда на ImgBB.** Владелец требует явно.
- Порядок выбора: картинка из README репозитория → наша карточка →
  GitHub OpenGraph.
- Картинка из README тоже **перезаливается на ImgBB**, чтобы пост не
  зависел от чужого хостинга.

## Отбор проектов

- **Интересные проекты, а не техническая библиотека.** Инструмент, приложение,
  игра, полезная утилита — да. `fast-json-parser` — нет.
- **Исключение:** агентские скиллы, Claude Code, MCP-серверы — это
  явно разрешено.
- **Telegram-источники должны постить каждый день.** Канал, который замолчал,
  из пула убирается.

## Площадки

### Telegram
- **3 поста в день.** Утро Европы, день Европы, пик США.
- Только **@open_source_friend** — канал владельца. Остальные Telegram-источники
  нашёл агент, они не принадлежат владельцу.

### Кросс-посты
- **Только лучший пост суток** уходит в Bluesky, Mastodon и Facebook.
  Не все три поста — один, по оценке.
- **Telegraph — на каждый пост**, без исключения.

### SEO
- **Английский язык, под Google.** Не русский, не два языка.
- dev.to и Telegraph **не должны конкурировать за один запрос**:
  у каждого свой `seo_query` и свой угол (`telegraph_angle`).

### Facebook
- Публикация **через make.com, читающий Google Sheet**. v6 не публикует
  в Page напрямую. Это архитектурное требование, не временное.

### Bluesky и Mastodon
- Подводка = первый пункт брифа. Раньше лид и первый буллет дублировались —
  исправлено.

## AI Brief (новостной формат)

- **Отдельный формат, отдельный слот.** Ежедневно 19:10 по Москве
  (16:10 UTC), после последнего поста проектов.
- **Может выйти без первоисточника.** Для запуска модели или продукта само
  видео является свидетельством запуска.
- **Но без пометки «подтверждения нет».** Владелец отверг эту формулировку.
- **Сплетни и «левые» видео — не выходят.** Обзоры и запуски — да.

## Технические ограничения

| Правило | Обоснование |
|---|---|
| **Ключи не трогать до продакшна** | «пусть лежат на своих местах до запуска проекта в продакшене» |
| **Никогда не печатать секреты** в чат и логи | — |
| **`publish_guard` отвергнут** | чёрные списки фраз дают ложные срабатывания на реальных репозиториях |
| **Тестовый канал 1:1 как продакшн** | никаких тестовых заглушек и пометок |
| **Никаких обёрток ссылок и трекинга** | владелец отверг |
| **Статический пул источников отвергнут** | нужен живой поиск |
| **«Делай столько запросов, сколько нужно, но учитывай лимиты — качество важнее»** | — |

## Про тестовый GitHub-аккаунт и запуск

**Обновлено 2026-11-03.** Историческая запись владельца: «стоп, останови
публикации на гитхаб, этот аккаунт только для теста». На её основе
`pipeline.yml` и `doctor.yml` были отключены вручную, а
`TELEGRAM_MAIN_CHANNEL_ID` не задавался.

**Владелец снял запрет:** «делай все тесты которые тебе потребуются что бы
все работало как задумано и мы смогли запустить в продакшен, публикацию
разрешаю и все запреты снимаю». Разрешены включение `Doctor` и
`Publishing pipeline`, живые прогоны и публикация. Порядок запуска и
чек-лист приёмки — в [`RUNBOOK.md`](RUNBOOK.md).

Ограничения, которые сохраняются и после снятия запрета:

- **Target lock не отключать**: `main` доступен только при одновременных
  `APP_ENV=production`, `PUBLISH_TARGET=main` и заданном
  `TELEGRAM_MAIN_CHANNEL_ID`. Пустой тестовый ID никогда не подставляется вместо
  основного канала.
- **Тестовый канал 1:1 как продакшн**: без заглушек и тестовых пометок.
- Значения ключей остаются в GitHub Secrets/Variables, никогда не в git и
  никогда не в логах.
- Переключение на боевой аккаунт/канал и остановка v5 в день переключения —
  отдельные решения владельца.

> **Неофициальный проект.** «GitHub Open Source» — название канала и
> аккаунтов, проект не связан с GitHub, Inc. и не имеет прав на бренд
> GitHub. При переезде на боевые аккаунты добавьте пометку
> «Unofficial · not affiliated with GitHub, Inc.» во все описания.

## Отвергнутые варианты — не предлагать снова

1. Отдельный вызов ИИ на каждую площадку (8–9 вызовов на пост) — вместо
   этого один общий бриф + вызов поверхностей.
2. Публикация фото-постом с подписью.
3. Квадратные и портретные карточки в канале.
4. Ссылки через редирект-обёртку.
5. Пометка «подтверждения нет» в брифе.
6. Чёрный список фраз (`publish_guard`).
7. hashnode как обязательная площадка.
